Task:
Take a screens CSV (output from proto-content-to-screens-csv, Stage 1) and produce an elements CSV. One row = one compositable image asset for a single prototype screen. Each row must include an image_gen_prompt for an image-generation AI.

This is Stage 2 of a two-stage prototype workflow. Stage 1 plans the screen flow; Stage 2 decomposes each screen into isolated UI elements with proportional bounding boxes and interaction metadata.

CRITICAL — text_to_render MUST appear inside image_gen_prompt:
- Keep both columns: text_to_render (spreadsheet column) and image_gen_prompt (paste at image-gen time).
- For every row, copy the text_to_render cell verbatim into the image_gen_prompt line that starts with Text to render:
- The human pastes ONLY image_gen_prompt — never text_to_render separately.
- If you put text only in text_to_render but omit it from image_gen_prompt, the output is WRONG. Reject and fix before delivering.

Column schema (authoritative — use exactly these columns in this order):

element_id;screen_id;element_order;z_index;element_type;bbox_x_pct;bbox_y_pct;bbox_w_pct;bbox_h_pct;text_to_render;state_variant;interaction_type;interaction_target;adjacency_notes;image_gen_prompt;assembly_notes

Column definitions:

- element_id: Stable primary key. Format EL_SCREEN_001_01, EL_SCREEN_001_02, etc.
- screen_id: Foreign key — must match a screen_id from the input screens CSV.
- element_order: Stacking / reading order on the screen (1 = first / back / top-left).
- z_index: Layer order (1 = back, higher = front). Overlays (modal, toast, FAB) use higher z_index.
- element_type: One of: status_bar, app_bar, nav_bar, tab_bar, sidebar, search_field, text_field, dropdown, checkbox, radio_group, button_primary, button_secondary, card, list_item, table, chart, avatar, badge, modal_shell, toast, divider, illustration, map, fab.
- bbox_x_pct: Left edge position as 0–100 % of parent screen viewport width.
- bbox_y_pct: Top edge position as 0–100 % of parent screen viewport height.
- bbox_w_pct: Width as 0–100 % of parent screen viewport width.
- bbox_h_pct: Height as 0–100 % of parent screen viewport height.
- text_to_render: Literal text that must appear in the image. Empty cell when no text. Same value must appear on the Text to render: line inside image_gen_prompt.
- state_variant: One of: default, hover, pressed, focus, disabled, error, selected, empty.
- interaction_type: One of: none, navigate, submit, toggle, open_overlay, filter, select, back, scroll.
- interaction_target: screen_id (SCREEN_###) or element_id (EL_SCREEN_###_##) when interaction targets another piece. Empty when interaction_type is none.
- adjacency_notes: Relational fit hints — e.g. flush below header, fills remaining height between sidebar and bottom nav.
- image_gen_prompt: Four-part template below. Must embed text_to_render verbatim.
- assembly_notes: Tool-agnostic placement — repeat bbox values, z_index, and how piece connects to neighbors.

Decomposition rules:

1. Never produce one element that represents an entire screen.
2. Every screen_id must have at least one element. Typical screens have 2–8 elements; overlays may add one extra high-z_index piece.
3. Respect decomposition_hints, visual_intent, and interaction_summary from the screens CSV.
4. Use viewport_width and viewport_height from the parent screen row when writing assembly_notes (e.g. bbox 8,82,84,8 on 390×844 viewport).
5. Populate text_to_render for any element whose image must show specific words, labels, placeholders, button text, or list item text — then copy that cell verbatim into image_gen_prompt.

Proportion / puzzle-piece rules:

1. bbox_*_pct values are the primary assembly contract. Non-overlapping siblings at the same z_index should tile without unintended gaps (±1% tolerance).
2. Overlaps only when z_index indicates overlay (modal, toast, FAB).
3. bbox_x_pct + bbox_w_pct must not exceed 100. bbox_y_pct + bbox_h_pct must not exceed 100.
4. Derive aspect ratio for Framing: from bbox proportions — e.g. bbox 100×12 → wide horizontal strip ~25:3.
5. adjacency_notes must describe how this piece connects to neighboring elements so images fit like puzzle pieces.

Interaction rules:

1. Any tappable or clickable control gets a non-none interaction_type and a valid interaction_target when navigation is known from screens CSV navigation_out.
2. Decorative or static pieces: interaction_type=none, empty interaction_target.
3. Submit buttons: interaction_type=submit, interaction_target=target screen from navigation_out when applicable.
4. Back buttons: interaction_type=back, interaction_target=screen from navigation_in when applicable.

image_gen_prompt template (MANDATORY — every row uses exactly these four parts in this order):
