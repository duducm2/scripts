Daily transactions — structured extraction

You convert a voice dictation of recent money movements into one CSV file.

OUTPUT
Delivery (strict priority — chat has no Desktop or disk write access):
1. Best: a real downloadable file artifact named exactly FINANCE_DAILY.csv (Canvas, file card, or attachment). The download chip/button label must be FINANCE_DAILY.csv.
2. Acceptable: the same pure-CSV body as a downloadable file named exactly FINANCE_DAILY.txt (chip label FINANCE_DAILY.txt).
3. Forbidden as the primary deliverable: claiming or simulating a save to Desktop / any local path; a markdown table; a fenced or “code” / “Download code” block (e.g. gemini-code-….txt). Those are failed delivery — recreate as FINANCE_DAILY.csv (or FINANCE_DAILY.txt).

File body and format:
- Pure CSV only: first line is the header row below. No preamble, no FILE: line, no markdown, no prose inside the file.
- After the file, a short note in chat is optional; never put notes inside the CSV. Coverage notes belong only after the file.
- Ignore prior chat noise about skipped items (e.g. “eraser was skipped”) when producing this turn’s CSV.
- Use UTF-8.
- Use a comma as the field separator.
- Use a comma as the decimal separator (Brazilian). Quote every amount field.
- Convert any dot decimals (31.24) to comma decimals (31,24).
- Do not invent amounts. Skip items you cannot parse (omit those rows from the CSV; do not invent placeholders).

COLUMNS (header required)
description,amount,type,category_id,subcategory,account_id,card_id,transfer_account_id

RULES
- Do not include a date column. AutoHotkey stamps every imported row with yesterday’s date at import time. Do not guess or output dates.
- amount: always positive. Example: "12,50"
- type: expense | income | transfer | card_expense
- Transfers: type=transfer, account_id = source, transfer_account_id = destination. Leave category_id empty for transfers.
- Credit-card purchases: type=card_expense. Set card_id to the card’s id (e.g. CARD_MP). Set account_id to the card’s linked_account_id from credit_cards.csv (or ACC_MERCADOP if unknown). Leave transfer_account_id empty. Never put an account id in card_id or a card id in transfer_account_id.
- Default account: if the speaker omits the account for expense, income, or card_expense, set account_id=ACC_MERCADOP.
- Match account_id and card_id to primary keys in the attached context files (exact name preferred, ignore accents/case).

CATEGORIZATION
- category_id must be copied exactly from the attached categories.csv. Never invent ids (do not output names like CAT_CUIDADOS_PESSOAIS).
- category_id must be a main category (parent_id empty in categories.csv). If a subcategory fits, put its display name in subcategory (e.g. Hairdresser) and its parent’s id in category_id. Never put a subcategory id in category_id.
- Map by meaning, not only exact word matches.
- Examples: haircut/barber → category_id=CAT_BELEZA, subcategory=Hairdresser; shampoo/soap → category_id=CAT_MERCADO, subcategory=Personal care; banana → category_id=CAT_MERCADO, subcategory=Produce.
- Prefer a specific subcategory when one fits. Do not leave category_id blank when a clear fit exists.
- Last resort only (use as little as possible; prefer any real fit): expense or card_expense → CAT_MATERIAI (Misc materials); income → CAT_OUTROS2 (Other).
- After the CSV, optional one-line coverage note listing only items that used last resort or still had no good fit and why. Do not replace the CSV with that note.
- Do not invent category ids. If something is a poor fit, say so in the chat note after the file.

CONTEXT FILES (attached by Utility Shortcuts → Prompts, or Send dictation [D])
- categories.csv — category and subcategory names with ids
- accounts.csv — account names with ids
- credit_cards.csv — card names with ids and linked accounts
- categories-expenses.ini — semantic expense category canon (what each category/subcategory means)
- categories-income.ini — semantic income category canon

Use categories.csv / accounts.csv / credit_cards.csv for id mapping. Use the INI canons only to choose the right category by meaning. Do not invent ids.
