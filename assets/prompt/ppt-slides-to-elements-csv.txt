Task:
Take a slides CSV (output from ppt-content-to-slides-csv, Stage 1) and produce an elements CSV. One row = one compositable element for a single slide. Rows are either PowerPoint-native text (no image) or image assets (with image_gen_prompt).

This is Stage 2 of a two-stage PowerPoint workflow. Stage 1 plans the deck; Stage 2 decomposes each slide into isolated visual elements.

CRITICAL — text-only vs image rows:
- Text-only element_types (leave image_gen_prompt EMPTY): title, subtitle, section_label, bullet_group, body_text_block.
- These are PowerPoint-native text: populate text_to_render and assembly_notes; do NOT write an image_gen_prompt.
- callout is image-capable (the only text-adjacent type that may get an image_gen_prompt).
- All other element_types require a non-empty image_gen_prompt using the four-part template below.

CRITICAL — text_to_render MUST appear inside image_gen_prompt (image rows only):
- Keep both columns: text_to_render (spreadsheet column) and image_gen_prompt (paste at image-gen time).
- For every IMAGE row, copy the text_to_render cell verbatim into the image_gen_prompt line that starts with Text to render:
- The human pastes ONLY image_gen_prompt for image generation — never text_to_render separately.
- If an image row puts text only in text_to_render but omits it from image_gen_prompt, the output is WRONG. Reject and fix before delivering.
- Text-only rows: skip this sync; image_gen_prompt stays empty.

CRITICAL — image_gen_prompt is subject and framing only for visual style (except human aesthetic comments). Brand prompts, JSON, and reference images the human attaches at image-gen time remain absolute authority for style packs. Do not invent aesthetic when the human did not provide aesthetic comments.

Before processing:

1. Confirm the slides CSV is present (paste or attach).
2. If the slides CSV is missing or lacks a slide_id column, stop and ask the user to provide it.

Inputs:

- Slides CSV: <paste or attach output from ppt-content-to-slides-csv>
- Optional assembly notes: <placement on slide only>
- Optional aesthetic comments: <if present, fold into Subject for image rows; if absent, keep Subject depiction general>

Column schema (authoritative — use exactly these columns in this order):

element_id;slide_id;element_order;element_type;position_region;size_hint;text_to_render;image_gen_prompt;assembly_notes

Column definitions:

- element_id: Stable primary key. Format EL_SLIDE_001_01, EL_SLIDE_001_02, etc.
- slide_id: Foreign key — must match a slide_id from the input slides CSV.
- element_order: Stacking / reading order on the slide (1 = first / back / top-left).
- element_type: One of: title, subtitle, section_label, bullet_group, body_text_block, metric_card, chart_bar, chart_line, chart_pie, icon_badge, illustration, diagram, timeline_segment, process_step, persona_card, comparison_column, callout, divider_line, decorative_shape.
- position_region: Placement hint — e.g. top, top_left, top_center, center, bottom_right, full_width_band, left_column, right_column.
- size_hint: One of: small, medium, large, full_width, full_height.
- text_to_render: Literal text for the element. Empty cell when no text. For image rows, the same value must appear on the Text to render: line inside image_gen_prompt. For text-only rows, this is the PowerPoint text to place.
- image_gen_prompt: Empty for text-only types (title, subtitle, section_label, bullet_group, body_text_block). For image types: four-part template below, with text_to_render embedded verbatim.
- assembly_notes: How to place this element on the slide.

Decomposition rules:

1. Never produce one element that represents an entire slide.
2. Every slide_id must have at least one element. Typical slides have 2–6 elements.
3. Respect decomposition_hints and visual_intent from the slides CSV.
4. For chart_focus or metric_dashboard slides, separate chart or metric_card elements — one chart per element.
5. Use data_points from the parent slide row for chart Subject lines.
6. Text-only types (title, subtitle, section_label, bullet_group, body_text_block): fill text_to_render; leave image_gen_prompt empty.
7. Image types: populate text_to_render when the image must show specific words, labels, dates, timeline entries, bullets, or data callouts — then copy that cell verbatim into image_gen_prompt.

image_gen_prompt template (MANDATORY for IMAGE rows only — exactly these four parts in this order):

Part 1 — concrete draw instruction (FIRST — image models must see this immediately):
Subject: [Concrete instruction of what to draw — object, scene, chart, diagram, or visual composition. Not a vague short label. If the human provided aesthetic comments in this message or optional notes, include that aesthetic here. If no human aesthetic comments, keep the depiction general — do not invent colors, fonts, materials, lighting, or brand style. Do NOT put the full text_to_render string only here.]

Examples of good Subject lines:
- Subject: Draw a horizontal timeline of the Titanic voyage with three marked events along a single axis.
- Subject: Draw a horizontal bar chart comparing regional share: EMEA, APAC, Americas.
- Subject: Draw an isolated side-view illustration of the Titanic ocean liner at sea.

Part 2 — copy verbatim:
HUMAN STYLE AUTHORITY: Any style requirements, brand prompts, JSON files, reference images, or instructions the human provided before or with this message define ALL visual style — colors, typography, illustration style, realism, materials, lighting, backgrounds, and quality rules. They override and replace any conflicting wording below except aesthetic comments the human explicitly included in Subject. Do not invent or substitute a different style.

Part 3 — COPY FROM text_to_render COLUMN (mechanical sync):
Text to render: [paste exact contents of text_to_render cell for this row, character for character]
If text_to_render cell is empty, write exactly: Text to render: none

Part 4 — framing:
Framing: isolated element only, not a full slide; [aspect ratio hint].

Join all four parts into one image_gen_prompt cell, separated by spaces (single paragraph). No fifth part.
