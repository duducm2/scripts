Task:
Take a slides CSV (output from ppt-content-to-slides-csv, Stage 1) and produce an elements CSV. One row = one compositable image asset for a single slide. Each row must include an image_gen_prompt for an image-generation AI.

This is Stage 2 of a two-stage PowerPoint workflow. Stage 1 plans the deck; Stage 2 decomposes each slide into isolated visual elements.

CRITICAL — text_to_render MUST appear inside image_gen_prompt:
- Keep both columns: text_to_render (spreadsheet column) and image_gen_prompt (paste at image-gen time).
- For every row, copy the text_to_render cell verbatim into the image_gen_prompt line that starts with Text to render:
- The human pastes ONLY image_gen_prompt — never text_to_render separately.
- If you put text only in text_to_render but omit it from image_gen_prompt, the output is WRONG. Reject and fix before delivering.

CRITICAL — image_gen_prompt is subject and framing only for visual style. The human supplies style separately (brand prompts, JSON, reference images). Human style inputs are absolute authority.

Before processing:

1. Confirm the slides CSV is present (paste or attach).
2. If the slides CSV is missing or lacks a slide_id column, stop and ask the user to provide it.

Inputs:

- Slides CSV: <paste or attach output from ppt-content-to-slides-csv>
- Optional assembly notes: <placement on slide only — not colors or illustration style>

Column schema (authoritative — use exactly these columns in this order):

element_id;slide_id;element_order;element_type;position_region;size_hint;text_to_render;image_gen_prompt;assembly_notes

Column definitions:

- element_id: Stable primary key. Format EL_SLIDE_001_01, EL_SLIDE_001_02, etc.
- slide_id: Foreign key — must match a slide_id from the input slides CSV.
- element_order: Stacking / reading order on the slide (1 = first / back / top-left).
- element_type: One of: title, subtitle, section_label, bullet_group, body_text_block, metric_card, chart_bar, chart_line, chart_pie, icon_badge, illustration, diagram, timeline_segment, process_step, persona_card, comparison_column, callout, divider_line, decorative_shape.
- position_region: Placement hint — e.g. top, top_left, top_center, center, bottom_right, full_width_band, left_column, right_column.
- size_hint: One of: small, medium, large, full_width, full_height.
- text_to_render: Literal text that must appear in the image. Empty cell when no text. Same value must appear on the Text to render: line inside image_gen_prompt.
- image_gen_prompt: Four-part template below. Must embed text_to_render verbatim.
- assembly_notes: How to place this element on the slide.

Decomposition rules:

1. Never produce one element that represents an entire slide.
2. Every slide_id must have at least one element. Typical slides have 2–6 elements.
3. Respect decomposition_hints and visual_intent from the slides CSV.
4. For chart_focus or metric_dashboard slides, separate chart or metric_card elements — one chart per element.
5. Use data_points from the parent slide row for chart Subject lines.
6. Populate text_to_render for any element whose image must show specific words, labels, dates, timeline entries, bullets, or data callouts — then copy that cell verbatim into image_gen_prompt.

image_gen_prompt template (MANDATORY — every row uses exactly these four parts in this order):

Part 1 — copy verbatim:
HUMAN STYLE AUTHORITY: Any style requirements, brand prompts, JSON files, reference images, or instructions the human provided before or with this message define ALL visual style — colors, typography, illustration style, realism, materials, lighting, backgrounds, and quality rules. They override and replace any conflicting wording below. Do not invent or substitute a different style.

Part 2 — brief label only (do NOT put the full text_to_render here):
Subject: [element type + short label, e.g. Titanic timeline, Q4 Results title, horizontal bar chart]

Part 3 — COPY FROM text_to_render COLUMN (mechanical sync):
Text to render: [paste exact contents of text_to_render cell for this row, character for character]
If text_to_render cell is empty, write exactly: Text to render: none

Part 4 — framing:
Framing: isolated element only, not a full slide; [aspect ratio hint].

Join all four parts into one image_gen_prompt cell, separated by spaces (single paragraph). No fifth part.

WRONG vs RIGHT (timeline example):

text_to_render cell: 1912 Apr 10 — Departure | 1912 Apr 14 — Iceberg | 1912 Apr 15 — Sinking

WRONG image_gen_prompt (missing Text to render line):
... Subject: Titanic timeline. Framing: isolated element only, not a full slide; wide horizontal strip.

WRONG image_gen_prompt (text only in Subject, paraphrased):
... Subject: Titanic timeline with departure, iceberg, and sinking dates. Framing: ...

RIGHT image_gen_prompt:
... Subject: Titanic timeline. Text to render: 1912 Apr 10 — Departure | 1912 Apr 14 — Iceberg | 1912 Apr 15 — Sinking. Framing: isolated element only, not a full slide; wide horizontal strip.

Pre-output row check (run for EVERY row before writing CSV):

1. Read text_to_render cell for this row.
2. If non-empty: confirm image_gen_prompt contains Text to render: followed by the identical string.
3. If empty: confirm image_gen_prompt contains Text to render: none
4. If check fails, fix the row before output.

FORBIDDEN in image_gen_prompt:

- Colors, hex codes, palettes, brand names, fonts, illustration-style adjectives, materials, lighting, backgrounds, quality rules
- Putting timeline labels, titles, or bullet text only in Subject without the Text to render: line
- Paraphrasing or shortening text_to_render inside image_gen_prompt

Validation (before output):

- Every slide_id in elements exists in the input slides CSV.
- No duplicate element_id values.
- Every image_gen_prompt contains all four parts: HUMAN STYLE AUTHORITY, Subject:, Text to render:, Framing:
- For every row where text_to_render is non-empty, image_gen_prompt contains that exact string after Text to render:
- No forbidden style language.

RIGHT: element_id, EL_SLIDE_001_01
