Bosch brand overview (embedded summary)

Brand intent:
- Create a uniform Bosch identity across touchpoints: "Many fibres. One rope. Many units. One brand."
- Reflect quality, clarity, functionality, and trustworthiness.
- Support the "Invented for life" promise: technology serving people.

Design principles (Brand Guide):
- Flat design: minimalistic, reduced to essentials; clear and open surfaces; rectangular shapes and clear edges.
- Less is more: use color and visual emphasis only where functionally needed; avoid clutter.
- High quality: precise alignment, high readability, deliberate layouts, no low-resolution assets.

BDDS scope:
- BDDS is the mandatory default for Bosch-branded digital touchpoints.
- Reuse official patterns and components; do not invent custom UI styles when BDDS patterns exist.
- Accessibility is baseline, not optional.

Geometry and surfaces:
- Prefer rectangular shapes and clear edges.
- Do not use decorative drop shadows.
- Do not use rounded corners as the dominant visual language (BDDS buttons use 0px border radius).
- Keep compositions open, functional, and easy to scan.

Typography:
- Use Bosch Sans (Regular for body, Bold for headings).
- Maintain high readability, precise alignment, and consistent hierarchy.
- Links: Bosch Blue (#007BC0), underlined.

Layout and spacing (digital):
- Use clear structure, functional hierarchy, and consistent spacing.
- Digital touchpoints follow rem-based spacing (1 rem = 16 px).
- Software layouts typically use a 12-column responsive grid with at least 1 rem margins and gutters.

Standard color starter guide

Foundation:
- White (#FFFFFF) — default background and neutral surfaces
- Black (#000000) — primary text
- Bosch Gray 50 (#71767C) — neutral UI, extended chapter color

Primary digital accent:
- Bosch Blue 50 (#007BC0) — links, buttons, navigation, information accents

Supergraphic accent colors (use one accent family per composition):
- Bosch Purple 40 (#9E2896)
- Bosch Turquoise 50 (#18837E)
- Bosch Green 50 (#00884A)

Restricted colors:
- Bosch Red 50 (#ED0007) — Bosch logotype and error states only; never as decorative accent

Functional / notification colors (states only, not decoration):
- Yellow (#FFCF00) — important notifications, warnings
- Green (#00884A) — positive feedback, success, tips
- Red (#ED0007) — errors
- Blue (#007BC0 / #00629A) — information, interactive accents

Color rules:
- Build on white, black, and gray; use color sparingly and purposefully.
- Use one accent color family at a time per composition.
- Do not use gradients. Use flat fills or discrete gradation steps from attached JSON when needed.
- Reserve warning and notification colors for their functional roles only.
- For exact gradation steps and diagram palettes, follow attached JSON context files.

Final quality double-check

Before delivering the image, verify every item below. If any check fails, revise before output:

1. The result looks professionally designed and aesthetically pleasant — not generic or obviously AI-generated.
2. Output resolution is sharp at the intended display size: 1920 x 1080 pixels minimum for 16:9 slides; other image types must be equally crisp at native size.
3. No blur, smear, noise, compression artifacts, or visual glitches — especially no soft halos or grayish fringes around buttons, icons, boxes, lines, or text against white backgrounds.
4. Flat UI elements use hard, vector-sharp edges and uniform solid color fills — no feathered anti-aliasing, gradient bleed, outer glow, ambient haze, or drop-shadow bleed at shape borders.
5. No bent, melted, warped, or inconsistent icons or symbols.
6. All text is readable at 100% zoom, correctly spelled, well-aligned, and uses Bosch Sans styling — no blurry glyph edges.
7. Colors match the Bosch palette above and attached JSON — no decorative red, no random gradients, no off-brand hues.
8. Shapes are mostly rectangular with clear edges; no shadow-heavy or rounded-corner-heavy aesthetic unless type-specific JSON allows it.
9. Layout is clean, aligned, and easy to crop or paste onto a white background.
10. The output matches the specified image type, user content, attached JSON rules, and reference imagery.
11. If any element shows a soft halo or low-resolution blur, revise and regenerate with sharper edges before delivering.
