# Memory Palace atoms CSV import

You are producing a **strict CSV** for the Memory Palace importer.

## Output rules (mandatory)

1. Output **CSV only**. No markdown fences, no commentary, no “FILE:” preamble.
2. First line MUST be exactly this header:

```
id,beast_id,kind,zone,zone_label,concept,quote,story,sensory,ipa,sort_order
```

3. Save guidance for the user (they will do this manually): Desktop file named `PALACE_ATOMS.csv`.
4. Each row is one **Knowledge Atom** attached to an existing `beast_id` from the attached beasts CSV.
5. `kind` is either `single` or `zoned` (legacy `subtopic` is accepted as `zoned`).
6. Mapping rule:
   - A beast carries **one** `single` Knowledge Atom, **or**
   - up to **exactly four** `zoned` Knowledge Atoms with zones `Z1`, `Z2`, `Z3`, `Z4` (never mix single + zoned on the same beast).
7. For `single`: leave `zone` and `zone_label` empty.
8. For `zoned`: `zone` must be `Z1`–`Z4`; put a short hook in `zone_label`.
9. Escape commas and newlines with standard CSV quoting.
10. Leave `id` empty if unknown (the importer will assign `ATOM_####`).
11. Pegs stay on beasts (not in this file). Never invent numeric pegs.
12. Do **not** invent `beast_id` values — only use IDs from the attached context.

## Knowledge Atom fields

- **Concept** — rehearsal definition
- **Quote** — verbatim source quote
- **Story** — mnemonic narrative / action
- **Sensory** — modality the story emphasizes (visual, auditory, tactile, …)
- **Beast** — comes from the parent beast row (`beast_id`), not a column in this CSV

## Vocabulary (software)

- **Study** — broad domain owning Memory Palaces.
- **Memory Palace** — location; one image per palace.
- **Character** — one per Memory Palace (canon characters.json).
- **Beast** — bestiary peg holder.
- **Knowledge Atom** — discrete information on a beast (Concept + Quote + Story + Sensory).
