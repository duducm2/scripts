# Memory Palace atoms CSV import

You are producing a **strict CSV** for the Memory Palace importer.

## Output rules (mandatory)

1. Output **CSV only**. No markdown fences, no commentary, no “FILE:” preamble.
2. First line MUST be exactly this header:

```
id,beast_id,kind,zone,zone_label,concept,keywords,quote,ipa,sort_order
```

3. Save guidance for the user (they will do this manually): Desktop file named `PALACE_ATOMS.csv`.
4. Each row is one **Knowledge Atom** attached to an existing `beast_id` from the attached beasts CSV.
5. `kind` is either `single` or `zoned` (legacy `subtopic` is accepted as `zoned`).
6. Mapping rule:
   - A beast carries **one** `single` Knowledge Atom, **or**
   - up to **exactly four** `zoned` Knowledge Atoms with zones `Z1`, `Z2`, `Z3`, `Z4` (never mix single + zoned on the same beast).
7. For `single`: leave `zone` and `zone_label` empty.
8. For `zoned`: `zone` must be `Z1`–`Z4`; put a short hook in `zone_label`.
9. Escape commas and newlines with standard CSV quoting.
10. Leave `id` empty if unknown (the importer will assign `ATOM_####`).
11. Pegs stay on beasts (not in this file). Never invent numeric pegs.
12. Do **not** invent `beast_id` values — only use IDs from the attached context.
13. `concept` — new rows only (`README §Knowledge Atom Structure`). Exactly two square-bracket groups that read as one sentence: `[I use {formal name} to {bare verb}] [{continuation}]`. Group 1 has no closing period. Group 2 continues that sentence and does not start a new “I …”. The name sits inside group 1, not in its own brackets. Optional ` — Note:` text stays unbracketed after the two groups. Do not rewrite attached legacy atoms into this shape.
14. `keywords` — required for new rows. Exactly two `Keyword | RecognizableWord` pairs joined by ` || `, one per bracket group, in left-to-right order. Pair 1’s RecognizableWord is the formal concept name. Pair 2’s RecognizableWord comes from group 2. Never put two keys in one group. Never key Note text.
15. Do **not** write a mnemonic narrative. If a `story` column is present in an attached file, leave it empty. The user writes stories later from the keywords.

## Knowledge Atom fields

- **Concept** — rehearsal definition for a new row (`[I use {Name} to {verb}] [{continuation}]` plus optional unbracketed Note). The two groups are one sentence.
- **Keywords** — exactly two tangible Keyword/RecognizableWord pairs (`Keyword | Word || Keyword | Word`). Pair 1’s word is the formal name; pair 2’s word comes from the continuation. The user writes any mnemonic story later from these keywords.
- **Quote** — verbatim source quote
- **Beast** — comes from the parent beast row (`beast_id`), not a column in this CSV

## Vocabulary (software)

- **Study** — broad domain owning Memory Palaces.
- **Memory Palace** — location; one image per palace.
- **Character** — one per Memory Palace (canon characters.json).
- **Beast** — bestiary peg holder.
- **Knowledge Atom** — discrete information on a beast (Concept + Keywords + Quote).
