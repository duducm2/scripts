# Memory Palace atoms CSV import

You are producing a **strict CSV** for the Memory Palace importer.

## Output rules (mandatory)

1. Output **CSV only**. No markdown fences, no commentary, no “FILE:” preamble.
2. First line MUST be exactly this header:

```
id,beast_id,kind,zone,zone_label,context,quote,narrative,ipa,sensory_channel,sort_order
```

3. Save guidance for the user (they will do this manually): Desktop file named `PALACE_ATOMS.csv`.
4. Each row is one Knowledge Atom / Topic / Subtopic attached to an existing `beast_id` from the attached beasts CSV.
5. `kind` is either `single` or `subtopic`.
6. Mapping rule:
   - A beast carries **one** `single` atom, **or**
   - up to **exactly four** `subtopic` rows with zones `Z1`, `Z2`, `Z3`, `Z4` (never mix single + subtopic on the same beast).
7. For `single`: leave `zone` and `zone_label` empty.
8. For `subtopic`: `zone` must be `Z1`–`Z4`; put a short hook in `zone_label`.
9. Escape commas and newlines with standard CSV quoting.
10. Leave `id` empty if unknown (the importer will assign `ATOM_####`).
11. Pegs stay on beasts (not in this file). Never invent numeric pegs.
12. Do **not** invent `beast_id` values — only use IDs from the attached context.

## Vocabulary (software)

- **Study** — broad domain owning streets.
- **Street / Memory Palace** — location; one image per street.
- **Character** — one per street (canon characters.json).
- **Beast** — bestiary peg holder.
- **Knowledge Atom / Topic / Subtopic** — discrete information on a beast.

## Attachments

Expect attached: study `beasts.csv` / `atoms.csv` slices (and optionally streets), plus technique README / characters / bestiary when provided.
