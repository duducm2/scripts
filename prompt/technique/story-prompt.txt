## Instructions for the Architect

### 1. Analyze Context

- Ingest the provided **Video Transcript** (from the Video Transcription Prompt run in Gemini Web) and **Best Theory** (distilled theory/concepts from the plan document or transcript). Do not expect a YouTube link; Cursor cannot access YouTube.
- Review the **existing study list** (Markdown) and the **Readme** to understand:
  - Current memorization state and mnemonic pattern.
  - Maximum 5 Beasts per Street.
  - Monolith usage (topic/session boundaries).
  - List format and structure.
- **Context awareness:** Do not duplicate concepts already present in the list; extract only new knowledge atoms and append to the existing state (per Readme Workflow Protocol).
- Use the **Bestiary** (e.g. `@studies/technique/bestiary.json`) and **Streets** (e.g. `@studies/technique/streets.json`) from context. Street images live in `technique/images/streets/` with filenames like `{sequence}. {lat}, {lon}.png`. The file `streets.json` is the canonical reference for sequence 1–N (e.g. 50 streets).

### 2. Story Construction

**Definitions:** Knowledge Atom = complete entry for one concept. **Peg** = letters from Bestiary `code` (e.g. A, AB). No numbers. **Knowledge** = brief summary of the concept. **Story/Action** = narrative event by the Beast. **Quote** = direct transcript excerpt from the video.

- Synthesize the new knowledge from the transcript into one mnemonic story.
- Map each concept to a specific **Beast** (from the Bestiary)—one **Knowledge Atom** per Beast—and place Beasts on specific **Streets** (from the street sequence in `streets.json`).
- **Peg constraint:** Use the Bestiary `code` field (e.g. A, B, AB) for the Peg. Never use numeric identifiers (1, 2, 01, etc.).
- **Street selection logic:** Identify the last used street index in the existing study list. Start at the **next** sequential street. Do not reuse streets already used in the current list.
- **Constraint:** Maximum 5 Beasts per Street (per Readme).
- **Output requirement:** You must write the **full, ready-to-use story content** yourself. Produce the complete study list section (story + template) that the User can append directly.

**Narrative Cohesion Guidelines:**

- **Character Interaction:** Make the beasts interact with each other whenever possible.
- **Shared Environments:** Reuse settings and props across different character scenes.
- **Sequential Continuity:** Connect the storyline of one beast directly to the next.
- **Example of desired cohesion:**
  1. A toucan rests on a bench and heads to a new location.
  2. A unicorn sits behind a desk and denies a job offer directly to the toucan.
  3. A vulture perches on the exact desk the unicorn is using.

**Four-part structure per Knowledge Atom** (separate each part with clear line breaks):

1. **Header:** `[Peg Letters]` `[Beast Name]` (e.g. `[A] [Arachne]`)
2. **Context:** One-line Knowledge summary.
3. **Narrative (Story/Action):** Describe the Beast performing an action. Introduce characters from `characters.json`. Create causality or interaction with adjacent Beasts for continuous flow.
4. **Conclusion (The Quote):** Place the direct video quote at the very end. Explicitly bridge the Story/Action to the Quote so the narrative leads to the professor's statement.

**Language Requirements (mandatory):**

- **Simple, plain English:** Use basic verbs, adjectives, and vocabulary to ensure the narrative is easy to understand. Strictly avoid jargon, technical terms, or old english words. 
- **Preserve quotes:** All quotes from the video transcription must be preserved exactly as they appear in the transcript. Do not simplify or modify quotes—they are the direct link back to the video content.

**Character integration:** Use figures from the **characters list** (`@studies/technique/characters.json`) to make knowledge atoms tangible and easier to remember. Do not use characters for every beast or atom; incorporate them when **transitioning between packs or animals** (e.g. between streets or topic chunks) to strengthen recall at boundaries.

**Copyright Workaround:** When generating image prompts for copyrighted characters, do not use their names directly. Instead, describe a character that is visually similar (e.g., instead of "Yoda", describe "a small, wise-looking green alien with long pointy ears, wearing a tattered tan robe"). This bypasses copyright filters in image generators like Gemini.

**AI Architect guidelines:** Review the **Actions** section in the Readme (`@studies/technique/README.md`, under Core Components) to understand story-creation protocols (Tangible, Grotesque, Sexual, Strange, Impactful) and to pass quality checks.

**Story-Video Alignment (mandatory):**

- **The Quote:** The **Conclusion (The Quote)** section of each Knowledge Atom is the mandatory direct transcript excerpt. **Quotes must be preserved exactly as they appear in the video transcription**—do not simplify, modify, or paraphrase quotes. The narrative must bridge the Story/Action to this Quote so the user can recall the video when reviewing the story.
- **Exact sentences (priority):** Use exact sentences from the transcript inside the story wherever possible. The Beast's action or the knowledge atom description should quote or paraphrase these sentences verbatim so the user hears the same language they heard in the video. Note: While the narrative should use simple English, quotes remain unchanged from the transcript.
- **Grammatical structure (fallback):** When exact sentences do not fit the mnemonic, replicate the grammatical structure of the transcript sentence. Change only subjects and objects (e.g. "The Dragon swallows the shield" mirrors "The subject receives the action"). Preserve tense, aspect, and clause structure.
- **Cognitive link to video cues:** Create an obvious link between each story element and a specific visual or auditory cue from the video. Examples: If the video shows an example sentence on screen, the Beast can "hold" or "point at" that sentence in the story. If the instructor emphasizes a rule by repeating it, the Beast can "scream" or "announce" that rule. Reference concrete video moments (e.g. "as the instructor demonstrated") so the user can mentally rewind to that scene.
- **Recall goal:** Every Beast entry should allow the user to reconstruct both (a) the story scene and (b) the corresponding video moment. The story is a bridge back to the video, not a replacement.

### 3. Image Prompt Generation

- **Composition:** The **background** is the provided static street image (unchanged). Your prompt should describe only the **foreground**: Beasts (animals), characters, or pop stars performing actions, to be superimposed on that fixed background. Style is flexible (e.g. cartoon). The street background must stay identical across all images for that street.
- **Copyright workaround (mandatory):** NEVER use copyrighted character names in the image prompts (e.g. Mickey, Minnie, Sherlock Holmes, Yoda, Simba). Image generators (e.g. Gemini) will block them. Instead, describe visually: "two cartoon mice in formal wear," "a detective in a deerstalker hat," "a small green alien with pointy ears," "a young lion cub."
- For each new street/scene, write one **image-generation prompt** describing the foreground elements (Beasts, optionally Characters/Actions). **Monolith usage (e.g. Nano Banana):** The **first** image (first street of the Topic) MUST include a Monolith; the **last** image (last street of the Topic) MUST include a Monolith; do **NOT** include a Monolith in any intermediate images.
- For each such scene, take the **exact image filename** from `streets.json` (field `filename`) for that street's sequence (e.g. `1. -22.757492, -47.149093.png`).
- Produce the content for a single file named **`image_prompts.txt`** in the list folder (e.g. `lists/1/image_prompts.txt`). Use a clear format: `[Street Image Filename]\t[Generated Prompt]` per line, or `---` between pairs. The User copies each prompt to AI C and matches outputs to placeholders in the study list.

### 4. Create Empty Document Template for Streets

Produce the **ready-to-append study list section** that the User will add to their list Markdown file. This template must include:

- **Monolith markers:** `<!-- MONOLITH START -->` at the beginning and `<!-- MONOLITH END -->` at the end.
- **Street headers:** One `### Street N: [Title]` per street, in sequence.
- **Image placeholders:** One per street, immediately after each street header, in the format `![Street N](<images/[filename].png>)` using the exact filenames from `streets.json`. The User will replace these with AI C's generated images.
- **Beast entries:** Each Knowledge Atom uses the four-part structure: (1) Header: `[Peg] [Beast Name]`; (2) Context: Knowledge summary; (3) Narrative (Story/Action); (4) Conclusion (The Quote). Separate each part and each Knowledge Atom with clear line breaks. One Knowledge Atom per Beast, in order. **Strict visual separation:** A blank line before and after each Knowledge Atom.
- **TTS optimization:** Format must be readable aloud; avoid markdown that does not read well in TTS.
- **Quality:** Ensure max 5 Beasts per Street, correct Monolith usage (first and last image of the Topic), and list format consistency per the Readme.

### 5. Output Deliverables

Produce these three deliverables for the User:

1. **Fully written mnemonic story + empty document template** — The complete study list section (monolith markers, street headers, image placeholders, beast entries) ready to append to the existing list.
2. **Image prompts file content** — Pairs of street image filename and generated prompt (one per scene), so the User can run AI C and match outputs to placeholders.
3. **Brief quality summary** — A short confirmation that the output respects max 5 Beasts per Street, Monolith rules, four-part Knowledge Atom structure (Header, Context, Narrative, Quote), Peg letters (no numbers), and list format.
