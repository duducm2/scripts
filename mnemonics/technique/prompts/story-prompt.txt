## Procedure

### 1. Analyze context

- Ingest the transcript. Do not expect a YouTube link.
- Apply README rules: Knowledge Atom Structure, Streets/Depth Slots (as Memory Palaces), Independent Beast Beats, Bizarreness Gate, Actions palette, Characters, Language & IPA, Peg conventions, Image composition.
- Extract only **new** knowledge; never duplicate concepts already in attached atoms/list.
- Build reserved character set from attached palaces before assignment.
- Load bestiary `code` for pegs.

### 2. Palace packing (minimize palace count) — HARD

Do this **before** writing stories or PREVIEW. Bad packing = failed delivery (importer rejects).

- Assign **exactly 5 beasts to each Memory Palace**.
- The **only** Memory Palace allowed to have fewer than 5 beasts is the **last one** (highest `palace_number` in this study after packing). Put the remainder there **only** when remaining beasts < 5.
- Worked example: 16 beasts → 4 palaces as `5 + 5 + 5 + 1` (the single beast on the **last** palace).
- **Invalid patterns (rewrite):** `1 + 5 + 5 + 5`, `1 + 5`, `2 + 5 + 5`, `4 + 5`, or any pack where an earlier palace has 1–4 beasts and a later palace exists. Especially forbidden: starting a new palace with only one beast while continuing a multi-palace sequence.
- Continuous / append sessions: if the study’s current last palace has 1–4 beasts, **fill that palace to 5 first** with new beasts before creating any higher-numbered palace. Never “park” a single new beast on a new palace while the previous one still has open slots.
- NEVER open a new palace while any earlier palace (by `palace_number`) has fewer than 5 beasts and ≥1 beast remains to place.
- Palace count = ceil(beast_count / 5). Set `depth_slots_used` to the beast count on that palace (1–5).
- In PREVIEW, beasts under each palace MUST total 5 except the **last** palace (which may list 1–4). Count peg groups under each `PALACE N` heading before send. If an earlier palace has fewer than 5 while a later palace exists, **rewrite the pack** — do not ship. The Desktop importer **rejects** that packing.

### 3. Story construction (encode into CSV rows)

- Map each concept to one beast — one Knowledge Atom per beast by default.
- Peg letters only; independent beast beats; Bizarreness Gate on every story.
- **Concept compression:** write `concept` at maximum compression (minimal word count, full meaning). NEVER drop essential conceptual logic. Prefer **first person singular** on the compressed core when it fits; skip when it would distort (`README §Knowledge Atom Structure`). If nuance/complexity must leave the compressed core to keep it ultra-short, append that supplementary context on `concept` as ` — Note: …` (Note stays impersonal). NEVER put the Note on `quote`.
- Story–video alignment: Quote is verbatim only; optional Note lives on `concept`; Story encodes meaning via action linked to a concrete video cue.
- Dual-access recall: peg → compressed concept (+ optional Note) → quote; palace image → encoding action → quote.

### 4. Image prompts

- One `image_prompt` per palace row: foreground only; depth slots + structural anchors; one character as a **lookalike** (`README §Image composition rules` — Character likeness / image-safety); plain English; bizarreness levers reflected.
- `character_name` keeps the canon name for recall. In `image_prompt` NEVER write that name (or any real/celebrity/historical/IP name). Use the lookalike formula: `an original fictional [role] who resembles [traits] — not any real, living, historical, or named public figure and not any copyrighted character`.
- Coordinate with prompt **g** (background preserve) when the human composites later — your job is the text in `image_prompt`.

### 5. Common failure modes (NEVER)

- NEVER assign two+ characters to one palace or reuse a character already used.
- NEVER invent `study_id` / `palace_id` / `beast_id` outside attached + this pack.
- NEVER use numeric pegs or cross-beast narrative dependency.
- NEVER under-fill a palace (1–4 beasts) when ≥5 beasts remain to place in this pack.
- NEVER leave a sparse palace (1–4 beasts) unless it is the **last** palace by `palace_number` (no higher-numbered palace may exist while an earlier one is under-filled).
- NEVER put a real person, celebrity, historical figure, or IP/franchise character **name** inside `image_prompt` (lookalike traits + disclaimer only).
- NEVER make Markdown streets the primary deliverable.
- NEVER emit three isolated CSV snippets without `===FILE: PALACE_…===` pack markers.
- NEVER omit the single `PALACE_PACK.txt` pack (download chip or one marked fence / gemini-code body).
