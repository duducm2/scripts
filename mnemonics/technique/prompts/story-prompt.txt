## Three CSV sections inside the pack (pure CSV only)

Each `===FILE: …===` body: UTF-8, comma separator, header row first, no preamble, no `FILE:` line, no markdown, no prose inside the section. Escape commas/newlines with standard CSV quoting.

### 1) `PALACE_PALACES.csv`

Header (exact):

```
id,study_id,palace_number,title,character_name,image_rel_path,depth_slots_used,image_prompt
```

Rules:
- Prefer `id` like `PALACE_<STUDY_SLUG>_<NN>` (e.g. `PALACE_VIOLIN_01`). Leave empty only if the importer must assign.
- `palace_number` — optional integer within the study (1, 2, …). Leave empty to let the importer assign the next free index. Prefer a stable `id` and a clear `title` (title is the human identifier).
- `character_name` — exactly one unused canon character per palace (file-wide uniqueness vs attached palaces + new rows).
- `image_rel_path` — relative to notes studies root when known (e.g. `violin/images/1.png`); leave empty if unknown (human may use Memory Palace **[Q]** later).
- `depth_slots_used` — 0–5 (beast count / depth slots for that palace).
- `image_prompt` — full foreground image prompt for that palace (Maps background is user-supplied). Put prompts here — not as a separate Markdown `🖼️` section. Character MUST use the lookalike formula (`README §Image composition rules`); NEVER paste `character_name` into this field.

### 2) `PALACE_BEASTS.csv`

Header (exact):

```
id,palace_id,peg_code,beast_name,beast_source,sensory_channel,is_smashed,sort_order
```

Rules:
- `palace_id` must match an `id` in this pack’s palaces file (or an attached existing palace).
- Prefer `id` like `BEAST_<palace slug>_<peg>`.
- `peg_code` — bestiary letter codes only (no numeric pegs); unbroken A–Z within the story scope per README.
- `beast_name` / `beast_source` from bestiary; `sensory_channel` from the atom’s topic sensory (visual, auditory, …).
- `is_smashed` — `0` for single-atom beasts; `1` when the beast carries zoned atoms.
- `sort_order` — order within the palace (1…).
- Max **5 beasts per Memory Palace** (`README §Streets and Depth Slots`).
- **Packing rule:** fill every palace to **exactly 5 beasts** before opening the next; fewer than 5 only when the remaining beast pool is < 5.

### 3) `PALACE_ATOMS.csv`

Header (exact):

```
id,beast_id,kind,zone,zone_label,concept,quote,story,sensory,ipa,sort_order
```

Rules:
- `beast_id` must match this pack’s beasts (or attached).
- `kind` — `single` or `zoned` (legacy `subtopic` → `zoned`).
- Mapping: one `single` atom **or** up to four `zoned` atoms (`Z1`–`Z4`) per beast — never mix on the same beast.
- `single`: leave `zone` and `zone_label` empty.
- `zoned`: `zone` = `Z1`–`Z4`; short hook in `zone_label`.
- Field mapping from technique prose:
  - **concept** ← rehearsal definition (`💡 Context`)
  - **quote** ← verbatim transcript excerpt
  - **story** ← Narrative (bizarre action encoding)
  - **sensory** ← modality emphasized
  - **ipa** ← German IPA when needed; else empty
- Leave `id` empty if unknown (`ATOM_####` assigned on import).

## Procedure

### 1. Analyze context

- Ingest the transcript. Do not expect a YouTube link.
- Apply README rules: Knowledge Atom Structure, Streets/Depth Slots (as Memory Palaces), Independent Beast Beats, Bizarreness Gate, Actions palette, Characters, Language & IPA, Peg conventions, Image composition.
- Extract only **new** knowledge; never duplicate concepts already in attached atoms/list.
- Build reserved character set from attached palaces before assignment.
- Load bestiary `code` for pegs.

### 2. Palace packing (minimize palace count)

- Assign **exactly 5 beasts to each Memory Palace**.
- Allocate fewer than 5 beasts to a palace **only** when the remaining pool of beasts to place is less than 5 (final palace only).
- NEVER open a new palace while a prior palace in this pack still has open slots and ≥1 beast remains.
- Palace count = ceil(beast_count / 5). Set `depth_slots_used` to the beast count on that palace (1–5).

### 3. Story construction (encode into CSV rows)

- Map each concept to one beast — one Knowledge Atom per beast by default.
- Peg letters only; independent beast beats; Bizarreness Gate on every story.
- Story–video alignment: Quote is verbatim; Story encodes meaning via action linked to a concrete video cue.
- Dual-access recall: peg → concept → quote; palace image → encoding action → quote.

### 4. Image prompts

- One `image_prompt` per palace row: foreground only; depth slots + structural anchors; one character as a **lookalike** (`README §Image composition rules` — Character likeness / image-safety); plain English; bizarreness levers reflected.
- `character_name` keeps the canon name for recall. In `image_prompt` NEVER write that name (or any real/celebrity/historical/IP name). Use the lookalike formula: `an original fictional [role] who resembles [traits] — not any real, living, historical, or named public figure and not any copyrighted character`.
- Coordinate with prompt **g** (background preserve) when the human composites later — your job is the text in `image_prompt`.

### 5. Common failure modes (NEVER)

- NEVER assign two+ characters to one palace or reuse a character already used.
- NEVER invent `study_id` / `palace_id` / `beast_id` outside attached + this pack.
- NEVER use numeric pegs or cross-beast narrative dependency.
- NEVER under-fill a palace (1–4 beasts) when ≥5 beasts remain to place in this pack.
- NEVER put a real person, celebrity, historical figure, or IP/franchise character **name** inside `image_prompt` (lookalike traits + disclaimer only).
- NEVER make Markdown streets the primary deliverable.
- NEVER emit three isolated CSV snippets without `===FILE: PALACE_…===` pack markers.
- NEVER omit the single `PALACE_PACK.txt` pack (download chip or one marked fence / gemini-code body).
