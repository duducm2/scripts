## Output contract

Produce **one Markdown document** following this exact skeleton (same shape as video transcription so prompt **4** can use it unchanged), top to bottom:

```md
# <Topic title>

**Source:** <URL, filename, or short description of the source>
**Language(s):** <e.g. English, or "German with English gloss">
**Curated from:** <transcript | article | notes | other>

## Overview

<2–4 sentences summarizing what this curated pack covers and what was cut (fluff / duplicates / already-known).>

## Discarded / merged (short)

- <one line per major merge or discard, or "none">

## <Concept 1 title>

<Short polished explanation in full sentences (2–5 sentences). Preserve depth; remove repetition.>

**Visual/auditory cue:** <omit line if none.>

**Examples:**

- <Concrete example 1 from the source, with any verbatim example sentences preserved>
- <Concrete example 2>

## <Concept 2 title>

...

## Exact sentences for story reuse

- "<verbatim sentence 1>" — <concept it belongs to>
- "<verbatim sentence 2>" — <concept it belongs to>
- ...
```

**Formatting rules:**

- Save output as `.md` — no code fences wrapping the entire document.
- Use `>` blockquote syntax for verbatim quotes so downstream tools can scan them.
- The `## Exact sentences for story reuse` section MUST include at least one verbatim quote per kept concept.
- Do not add tables of contents, disclaimers, or meta-commentary about the curation process.
- After delivery: one short chat line only — tell the human to save as `.md` and attach it as **Video transcription** when running Creating mnemonic stories (**4**).

## Procedure

### 1. Inventory candidate atoms

- Read the entire source. Do not skip sections.
- List every distinct teachable unit: definition, rule, formula, distinction, procedure step, named framework piece.
- Prefer atoms that can become one Knowledge Atom (`README §Knowledge Atom Structure`): clear Concept + a real Quote from the source.

### 2. Curate (merge / drop — do not under-extract)

- **Merge** near-duplicates and restatements into one concept section (keep the strongest verbatim quote).
- **Drop** filler, anecdotes, and motivational asides that are not rehearsal targets.
- **Skip** concepts already present in the attached practice / study inventory (note them under Discarded / merged).
- **Keep** every remaining distinct rehearsal-worthy atom. NEVER collapse a rich multi-concept source into a tiny handful when many distinct atoms remain.
- There is **no** maximum concept count. Density comes from quality filters above, not from a target like “aim for 4.”

### 3. Preserve verbatim sentences

- For each kept concept, include at least one **exact** quote from the source.
- Quotes MUST match the source word-for-word. NEVER paraphrase, “clean up,” or shorten a quote and label it verbatim.
- Prefer quotes that define or exemplify the concept (good Story Architect payload).

### 4. Note visual and auditory cues

- When the source is a video transcript and cues exist, keep or restore `**Visual/auditory cue:**` lines.
- For non-video text, omit the cue line unless the source itself describes a memorable visual/audio moment.

### 5. Language handling

- Keep source-language quotes intact.
- For non-English quotes, add an **English gloss** in parentheses after the quote when helpful for the Architect.
- **German:** authored prose gets inline IPA in `[…]` after German words/short phrases; inside quotes never insert IPA — use a following `IPA:` line (same rules as video transcription).

### 6. Style

- Polished, cohesive, concise. Full sentences in explanations.
- Plain vocabulary in your own prose; keep jargon only when it appears inside a preserved quote.
- Optimize for **downstream reuse**: Story Architect will scan `>` blockquotes and `## Exact sentences for story reuse`.

### Common failure modes (NEVER do these)

- NEVER invent quotes that are not in the source.
- NEVER paraphrase a source sentence and label it as a quote.
- NEVER under-extract (e.g. 3–4 concepts from a long multi-topic source) when many distinct atoms remain after curation.
- NEVER wrap the whole document in a single code fence — output raw Markdown.
- NEVER add meta commentary (“As requested, here is the curated list…”).
- NEVER emit a `PALACE_PACK` / CSV — that is Story Architect’s job.
- NEVER modify a German quote to insert IPA inside it — use the separate `IPA:` line.
